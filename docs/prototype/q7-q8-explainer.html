Q7「替换引导页正文」是什么意思？打开右侧栏看到什么

dsh 右侧栏在「没有指定要打开的内容」时，会显示一个起始页（框架自带的"引导页"：一列扁平胶囊，每个胶囊是一个插件入口）。 框架提供了一条正式扩展点：插件可以整页接管这个起始页的正文。所以有两种做法：
❌ 我之前做的（错的）
📄 文件💻 终端 🔧 工作台＋
右侧栏里多出一个「工作台」标签；起始页还是框架原来的胶囊列表；
要点开「工作台」标签，才看到分类界面。
📄 文件💻 终端🔧 工作台 ← 多一层
✗ 多了一层：右侧栏 → 工作台标签 → 分类 → 内容
✅ 你要的（替换起始页）
📄 文件💻 终端＋
▾ 工作台
个人工作台故障排查交易
▾ 工程与任务
任务终端Git
▾ 浏览与工具
浏览器语音转文字
✓ 打开右侧栏 → 直接就是分类界面（起始页被整个替换）
一句话：「替换」= 把框架自带的那张起始页（扁平胶囊列表）换成我们的分类界面。 不新增标签、不套一层；右侧栏打开后第一眼看到的就是分组后的所有插件入口。
顺带效果：其他插件原来贡献的扁平胶囊不再单独出现——入口统一由分类框架组织（这正是「彻底分组」）。

Q8 条目从哪来？自动发现 vs 手工清单举例

假设你机器上装了这些插件（每个插件向右侧栏注册一个「类型」，例如 kind='personal-workbench'）：
已安装插件（注册表里能查到）
personal-workbenchtroubleshoot-workbench trading-workbenchaudio-transcriber audio-ttsfiles(官方) terminalgit
做法 它怎么工作 今天装了上面 8 个插件 明天新装一个「翻译插件」kind='translator'
A 自动发现
（推荐）		 hub 启动时问一次注册表：SidebarRightTabs.entries() → 拿到全部已注册类型；
再按一张映射表把类型分到各组；映射表里没有的 → 进「其他」组		 分类界面自动列出 8 个条目，按映射表归组（工作台组 3 个、浏览与工具组 2 个…） 自动出现，落在「其他」组（因为映射表没登记它）——不用改 hub 代码
B 手工清单 hub 代码里写死名单：[{kind:'personal-workbench', group:'工作台'}, …] 同左（但名单是我们手写的） 不出现，除非我们改 hub 代码、重新打包安装
C 插件自注册 hub 暴露一个服务，其他插件主动来登记「我是什么、属于哪组」；hub 只做兜底 需要每个插件配合改一行代码来登记 需要「翻译插件」自己改代码登记（不改就进「其他」组）
我推荐 A：因为它符合你说的「里面的条目是各种外部和我们之前开发的各种插件」——装什么就自动有什么， hub 只需要维护一张「哪个 kind 属于哪个组」的映射表（8 个已知插件的 kind 都是确定的，直接映射）。
