## 1. 旧 settings 配置契约（≤ v0.1.6，v0.1.7 起失效）

被删原文（AGENTS.md 关键契约）：

```
- 配置：host `ctx.settings.register(ns, schema, { base })`（第三参是 **options**）；client
  `ctx.settingsScope.bind({namespace})` → `getSnapshot / subscribe / mutate / unset`。
```

```
设置页卡片维护，配置存 DSH settings 的 `dsh-sidebar-hub` 命名空间。本插件只做**入口编排**——
```

删除原因：这两条描述的是「命名空间 = 包名 + `settingsScope` + `SettingsForms.register()`」的旧契约。
上游 0.2.0-rc.2 移除了 `settingsScope` 与 `register()`，本插件 v0.1.7 起改为：

- 命名空间 = **profile 条目 id**（`cordis.patch.yml` 的 `id: sidebar-hub`），旧包名 `dsh-sidebar-hub` 退役；
- client 经 `ctx.configForms.get('sidebar-hub')` 绑定；
- host 导出 `Config`（设置字段标 `.volatile()`），由上游 `SettingsForms.describe()` 按 `entry.options.id` 自动发现；
- 设置页卡片 key 另用 `SETTINGS_CARD_KEY`（= 包名）。

同一段历史的完整复盘另见（未改动）：[../管理/RMP-风险管理.md](../管理/RMP-风险管理.md) 的
「2026-09-25 分类页一直标「未持久化」」与「2026-10-01 settingsScope 接口被上游移除」两条，
以及 [../需求/BRD-003-upgrade-drift-sync.md](../需求/BRD-003-upgrade-drift-sync.md) 的「修订（v0.1.7）」节。

## 2. 旧 web 服务注入名（`webRuntime`，0.2.1-alpha.2 起失效）

被删/被改写的原文（AGENTS.md 红线、README.md 宿主面）：

```
- `/shub/api` 信封由 host `wire.ts: writeOk` 写 `{ok:true, value}`；网络面仅 `/shub/file`（md 图片）与
  `/shub/bundle`（mermaid chunk）。
```

```
- `/shub/api/<method>` JSON 网关（`{ok:true, value}` 信封，session/fs 基础）+ `/shub/file`（md 图片）
  + `/shub/upload` + `/shub/bundle`（惰性 chunk），全部前置信任围栏。
```

上游 alpha.2 删除了 `webRuntime` 服务（改由 `web-startup` 提供 `webStartup`），本插件 v0.1.8 完成
`inject: ['webRuntime']` → `['webStartup']` 迁移；现行路由清单为 `/shub/api`、`/shub/file`、
`/shub/html`、`/shub/upload`、`/shub/bundle`、`/shub/ws/agent-opens`。
